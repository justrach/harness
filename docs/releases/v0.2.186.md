# Harness v0.2.186

## Highlights

- **Bots, experimental and off by default (`crates/engine/src/bots.rs`, `crates/proto/src/bots.rs`, `apps/nano/src/bots.zig`, `apps/nano/src/view_bots.zig`, `apps/nano/src/view_bots_page.zig`, `docs/bots.md`)**:
  - A Bot is a standing role you message from any project: one job, its own memory, routines it starts by itself, and one standing chat. Bots are graff's (`graff bot --user`, kept in `~/.graff/bots`); Harness runs them and keeps nothing itself. Needs graff 0.302.74.61 or later.
  - **Off until you turn them on.** Settings › Agents has an `Experimental: Bots` card with one switch. It is graff's switch (`graff bot enable`, the file `~/.graff/bots/enabled`), so a terminal and the app agree. While it is off the engine starts no graff for bots, checks no routine, and the window is as it was: no Bots group, no catch-up. Turning it off keeps every bot, its memory and its routines.
  - With bots on, a **Bots group** sits in the sidebar under the chats on every project filter. A row shows the bot, the project it works in, and what it needs: a question waiting, a failure, a finished run not yet read, a routine that did not run. A bot's standing chat is listed there, with a strip naming the bot.
  - A **catch-up** lists what needs looking at, most pressing first. A launch that follows a stretch in which nothing checked routines opens on it and says between which times nothing was checking.
  - A **bot's page** has its job, routines (pause, run now, delete, add), memory with Forget, what all bots know about you, and its recent log. **New bot** takes a name and a job, in the project the sidebar is filtered to.
  - The engine checks routines once a minute while it runs. A slot that came due more than five minutes before a check is not run late; it is recorded as missed and shown as `Did not run`, with Run now and Dismiss. Routines run only while Harness is open.
  - Approvals follow the chat: a bot's own skip-approvals flag never reaches one.
- **Bots tools reach your own bots (`crates/mcp/src/tools/bots.rs`, `docs/mcp.md`)**:
  - With no project named, `list_bots` also returns your own bots as `yours`, and `run_bot` for one of them puts the turn into that bot's standing chat. While bots are off the three tools return graff's refusal and run nothing; an agent cannot turn bots on through them.

## Limits

- The primary bot waiting for a yes before it hands work to another bot is an instruction in its standing text, not something the engine enforces.
- Bots kept in one project's `.graff/bots` are not in the Bots group; the MCP tools still reach them by project.
- The phone apps do not show bots. Schedules are a delay or `@every` and a period; there are no weekday or clock times.
