# v0.2.85 stable release checklist

> Historical. Current releases follow [stable-release.md](stable-release.md).

This checklist is for the operator preparing the signed Apple silicon desktop
download. `scripts/stable_macos_release.py prepare` changes local files only;
`upload` requires an existing **draft** GitHub release and never publishes it.
Do not tag or publish v0.2.85 until Codegraff v0.0.302.5 is a public stable
release and its macOS CLI asset and `SHA256SUMS` are available.

1. Start from a clean Harness checkout at the reviewed v0.2.85 release commit.
   Confirm `Cargo.toml` says `0.2.85`. Run the normal Rust tests and the offline
   manifest tests:

   ```sh
   python3 -m unittest discover -s scripts -p 'test_stable_macos_release.py'
   cargo test -p harness-update
   cargo test -p harness --bin harness bundled_graff
   ```

2. On the signing Mac, use a Developer ID Application identity and the existing
   `codedb-notary` keychain profile. Point packaging at the **versioned**
   Codegraff release so it cannot silently pick up a newer `latest`:

   ```sh
   export CODESIGN_IDENTITY='Developer ID Application: <your signing identity>'
   export NOTARYTOOL_PROFILE=codedb-notary
   export GRAFF_RELEASES_URL='https://github.com/justrach/codegraff/releases/download/v0.0.302.5'
   scripts/package-macos.sh
   ```

   Packaging downloads `graff-aarch64-macos.tar.gz`, verifies it against that
   release's `SHA256SUMS`, signs any unsigned nested code, notarizes both the
   app and DMG, and staples both. The app tarball is made after app stapling.
   The script fails if notarization is configured without Developer ID signing.

3. With no CI signing secrets, the `v0.2.85` tag workflow builds the Linux and
   Windows artifacts, records that macOS needs local signing, and skips the
   publishing job successfully. It creates no public release or unsigned macOS
   download. Collect the four companion artifacts from that same v0.2.85
   source revision into `target/release-companions/`. Their exact names are:

   ```text
   zeron-0.2.85-linux-aarch64.tar.gz
   zeron-0.2.85-linux-x86_64.tar.gz
   zeron-0.2.85-windows-x86_64.exe
   zeron-0.2.85-windows-x86_64.zip
   ```

   The internal filenames retain their existing `zeron-` compatibility prefix
   in this release. Check the CI job commit matches the intended tag commit.

4. Prepare the upload directory. The helper validates the app's bundle ID and
   version, Developer ID signatures, hardened runtime, secure timestamps,
   app and DMG staple tickets, the DMG checksum, the app mounted from the
   DMG, and the extracted updater tarball. It compares both executable hashes
   across all three app copies and requires exactly Graff v0.0.302.5.
   It then creates a byte-identical stable DMG alias and a `manifest.json`
   containing SHA-256 checksums for every release asset:

   ```sh
   python3 scripts/stable_macos_release.py prepare
   ```

   Expected output directory: `target/stable-release/v0.2.85/`. A failed check
   is a stop condition. Do not replace it with an unsigned artifact.

5. Create an unpublished draft release for tag `v0.2.85` after the tag points
   at the reviewed commit. If the tag workflow already created a release,
   inspect it first; the helper only uploads to a draft. For a manual draft:

   ```sh
   gh release create v0.2.85 -R justrach/harness --draft \
     --title 'Harness v0.2.85' --notes-file docs/releases/v0.2.85.md
   python3 scripts/stable_macos_release.py upload
   ```

   `upload` rechecks the staged hashes and Apple artifacts before replacing
   assets on the draft. It leaves the draft unpublished. Inspect the asset
   list and release text in GitHub, then publish the draft deliberately.

6. After publication, read back the public stable release. Confirm
   `manifest.json` reports `0.2.85`, includes the
   `harness-0.2.85-macos-arm64-app.tar.gz` SHA-256, and that
   `Harness-macos-arm64.dmg` downloads. Install the DMG on a clean Mac, open
   Harness once, and confirm both the GUI and `graff --version` work in a new
   terminal. Check the app's update UI against the stable feed.

The tag workflow can perform the build and publication itself when all signing
and notarization secrets are configured. With none configured, it skips macOS
packaging and publication without failing the tag run. The local helper is for
a reviewed manual draft path;
it does not change the managed installer feed.
