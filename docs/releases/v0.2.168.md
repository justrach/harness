# Harness v0.2.168

Less lag on Macs, especially on fast displays and with several agents at work, and selecting text in a reply no longer fights the composer.

## Less lag

- On macOS 14 and later, Harness draws each frame into a buffer the display hands it when it's ready, instead of waiting for one on the main thread. On recent Macs that wait took a large share of every frame, so typing, scrolling and clicks lagged. (#731)
- A working agent's spinner no longer redraws the whole window at your display's full rate. While you're not typing, clicking or scrolling, animation runs at 60 frames a second; your own input still gets the full rate (120 Hz on ProMotion, 240 Hz where the display supports it). With several split panes of agents at work, this takes most of the load off the app. (#731)
- Each frame does less work: element ids are hashed once instead of on every lookup, and glyphs are sorted for drawing in about two-thirds of the time. (#731)

## Desktop

- Selecting text in a reply clears the composer's selection, and Copy copies what you selected last, in the window you selected it in. (#718)
